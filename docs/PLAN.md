# План портирования Uzebox на Karabas Go / Mini / Mini G

Статус: 2026-11-19, проект создан, **ждём выбора вариантов** (раздел 3). После выбора решения фиксируются в
разделе 4, работа идёт по фазам раздела 5 (одна ветка на фазу, один PR в конце).

## 1. Что такое Uzebox (исходные данные)

- Консоль из одного ATmega644 (64 КБ flash, 4 КБ SRAM, 2 КБ EEPROM) на **28.63636 МГц** (8 × NTSC burst) +
  AD725 RGB→NTSC. Кадрового буфера нет: картинку рисует программа, выводя пиксели в PORTC
  (цвет 3:3:2) с точностью до такта; синхро — PB0, строка = **1820 тактов** (15.734 кГц), 262 строки, 59.94 Гц.
- Звук: 5 каналов, микшируются программно раз в строку, выход — ШИМ таймера 2 (OCR2A), ~15.7 кГц, 8 бит.
- Ввод: два SNES-джойстика (сдвиговые регистры на PORTA), SNES-мышь, PS/2 клавиатура через адаптер на порту 2.
- Периферия: SD по SPI (FAT, Bootloader5 прошивает игру `.uze` в flash через SPM), SPI RAM 23LC1024 (128 КБ),
  UART0 → ESP8266 (Uzenet), MIDI IN.
- Готовой FPGA-реализации Uzebox нет (поиск 2026-11-19). Эталон поведения — эмулятор `upstream/uzebox/tools/uzem`
  (`avr8.cpp`, потактовый). Игры и тесты — `upstream/uzebox/demos`. Подробно: заметка `reference-uzebox-upstream`.

## 2. Что дают платы

Все три платы (XC6SLX25, ISE 14.7): 2 МБ SRAM (MA/MD), SDRAM, SD-карта на выводах ПЛИС (`SD_*`), ESP8266 на UART
(`UART_RX/TX/CTS`), MCU-линк v2 (OSD, USB-клавиатура/мышь/джойстики, загрузка файлов), I2S-ЦАП, HDMI (Mini, Mini G) /
VGA (Go). MIDI только на выход — MIDI IN Uzebox не переносим.

Хорошее совпадение: строка Uzebox × 2 = **31.47 кГц, 525 строк, 59.94 Гц — ровно частоты VGA 640×480**.
Значит, простой удвоитель строк даёт стандартную развёртку без кадрового буфера.

## 3. Варианты (нужен выбор)

### 3.1 Процессор AVR (главное решение)

| | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **A** | **Своё ядро ATmega644** (Verilog-2001 под XST), потактово как в даташите; uzem — оракул (сравнение трасс PC / такт / запись в порт) | полный контроль над таймингом прерываний и таймеров (на этом стоит весь Uzebox); всё под GPL-3; AVR прост (~130 команд) | больше работы на старте (оценка: ядро ~2 недели вечеров до прохождения unittest) |
| B | Взять **cmstar0/atmega-xmega-soft-core** (GPL-2+, потактовый, проверен на Arduboy_MiSTer) | ядро уже проверено играми | под Altera (`lpm_mux` в таймерах), XST-совместимость неизвестна; периферию ATmega644 (timer1 CTC, timer2 PWM, SPI, UART0, SPM) всё равно писать/править; чужой код отлаживать |
| C | softavrcore (LGPL) / nanamake avr_cpu | малы | **не потактовые** — для Uzebox не годятся |

**Рекомендую A**, с uzem как эталоном; из B можно подсматривать решения, но не копировать.

### 3.2 Видео

| | Вариант | Суть |
|---|---|---|
| **V1** | **Удвоитель строк 1:1 по тактам** | PORTC пишется в строчный буфер на каждом такте CPU (1820 байт = 1 BRAM), выводится дважды на 57.27 МГц (2× CPU): 1440×480 активных, 31.47 кГц, 59.94 Гц. Без кадрового буфера, задержка полстроки, все видеорежимы (4…8 тактов на пиксель) без искажений. HDMI как CEA 1440×480p (VIC 14/15 близок по частотам строк/кадров), VGA на Go |
| V2 | Кадровый буфер в SRAM | вывод стандартным 720×480p@27 МГц / 640×480; масштабирование, лишний кадр задержки, разрывы |
| V3 | Удвоитель с выборкой каждые 2 такта | 720 пикселей, но режимы с 5 тактами на пиксель дают неравные пиксели |

**Рекомендую V1.** Проверить на телевизоре/мониторе пользователя; запасной путь — V2.

### 3.3 Программная память и загрузка игр

| | Вариант | Суть |
|---|---|---|
| **M1** | **flash 64 КБ в BRAM** (32 из 52 RAMB16) | выборка за такт, LPM/SPM просто; SRAM 4 КБ и EEPROM 2 КБ тоже в BRAM |
| M2 | flash во внешней SRAM | экономит BRAM; 10 нс SRAM на 28.6 МГц успевает, но делить шину с SPI RAM и загрузчиком |
| **L1** | **Игра `.uze` через OSD** (элемент `FL`, MCU читает файл с SD и шлёт в ядро) | ядро пропускает 512-байтный заголовок, пишет в flash, сбрасывает AVR. Быстрый старт, SD ядру не нужна |
| L2 | **Родной Bootloader5** | меню Uzebox на SD; нужны SPI SD на выводах ПЛИС, SPM, секция загрузчика. Аутентично, нужно и для игр, читающих SD (Uzeamp и др.) |

**Рекомендую M1 + L1 в Ф1, L2 — в Ф2** (обе остаются: OSD-загрузка и Bootloader5).

### 3.4 Остальная периферия (решение по умолчанию, можно поправить)

- Джойстики: USB-джойстики MCU-линка → модель двух SNES-контроллеров на PORTA (клавиатура как джойстик 1).
- Звук: берём значение OCR2A напрямую (без ШИМ) → 16 бит в HDMI / I2S; простой ФНЧ как RC на плате Uzebox.
- SPI RAM 23LC1024 → в SRAM платы. EEPROM — в BRAM, сохранение на SD — позже.
- UART0 → ESP8266 платы (Uzenet работает «как есть», если прошивка ESP совместима).
- SNES-мышь, PS/2-клавиатура (из USB-клавиатуры) — в Ф4.

## 5. Фазы (для рекомендованных вариантов A + V1 + M1/L1)

- [ ] **Ф0. Ядро AVR в симуляции.** Ядро ATmega644 + таймеры 0/1/2, прерывания, порты; Verilator-стенд грузит
  `.hex`, пишет трассу и кадры (PORTC → PNG). Сверка с uzem: `unittest`, затем Megatris / SpriteDemo — PC и такт
  каждой записи в PORTC/OCR2A совпадают. Сборка XST только ядра: LUT и Fmax ≥ 28.64 МГц (цель 57 МГц с запасом).
- [ ] **Ф1. Mini G: играбельно.** Верх, PLL (50 МГц → 28.636 = 50·63/110 и 57.27 МГц), flash/SRAM/EEPROM в BRAM,
  загрузка `.uze` через OSD, удвоитель строк → HDMI, SNES-джойстики, звук, OSD-меню (игра, сброс, пауза?).
  Проверка: Megatris, Arkanoid, DonkeyKong, видеорежимы 1/3/9/13 на плате.
- [ ] **Ф2. SD и Bootloader5.** SPI SD (вопрос: общий доступ к карте с MCU), SPM, секция загрузчика,
  SPI RAM в SRAM, EEPROM. Проверка: меню Bootloader5, SDCardDemo, SPIRamTesterDemo, Uzeamp.
- [ ] **Ф3. Go и Mini.** Верхи генерируются из верха Mini G (как `mktops.py` в agon); VGA на Go, сборка всех плат.
- [ ] **Ф4. Uzenet, клавиатура, мышь.** UART0 ↔ ESP8266, PS/2-клавиатура из USB, SNES-мышь. Проверка: UzenetDemo,
  UzeboxPC.
- [ ] **Релиз.** `uzebox.kg`, README, публикация (по решению пользователя).

## 6. Открытые вопросы

- Как ядро и MCU делят SD-карту (Ф2)? Посмотреть, как это сделано в tsconf / nanomig.
- Принимают ли HDMI-приёмники 1440×480 на 57.27 МГц (не ровно 54 МГц CEA)? Проверить на Ф1; запас — V2.
